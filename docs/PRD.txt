2. Project Overview
HumanWriter is an AI/NLP system designed to analyze machine-generated or highly machine-like text and transform it into more natural, readable and stylistically varied writing while preserving the original meaning. The flagship technical component is a custom decoder-only Transformer language model of approximately 40 million parameters, designed and trained by the project team rather than accessed through a commercial LLM API. The project combines a from-scratch language-modeling pipeline with task-specific fine-tuning, text analysis and objective evaluation.
3. Problem Statement
Machine-generated text can be grammatically correct but may exhibit repetitive phrasing, predictable sentence structures, limited stylistic variation and unnatural readability. Existing AI-writing tools often depend on external commercial APIs, making the underlying model and training process difficult to study or control. HumanWriter addresses this by developing a self-contained NLP system whose model architecture, tokenizer, training pipeline, fine-tuning process and evaluation framework are controlled within the project.
4. Aim
To develop and evaluate a custom approximately 40M-parameter decoder-only Transformer language model that can perform natural-language transformation while maintaining semantic meaning, supported by a separate writing-analysis and evaluation pipeline.
5. Objectives
Design and implement a decoder-only Transformer architecture targeting approximately 40M trainable parameters.
Develop and train a custom subword tokenizer, such as BPE, suitable for the selected corpus.
Create a high-quality, legally usable corpus of human-written text from public-domain or appropriately licensed sources.
Implement preprocessing, cleaning, deduplication, filtering and train/validation/test dataset pipelines.
Pretrain the custom model using causal language modeling and next-token prediction.
Create a task-specific dataset for natural-language transformation using appropriately sourced or generated paired examples.
Fine-tune the pretrained model for controlled rewriting while preserving semantic meaning.
Develop a writing-analysis module that measures readability, sentence variation, vocabulary diversity, repetition and related linguistic features.
Develop an evaluation framework covering language-model quality, semantic preservation and writing quality.
Compare the custom model with at least one larger pretrained baseline without relying on an external inference API.
Develop a local application through which users can analyze and transform text.
Document experiments, limitations, hardware constraints, ethical considerations and reproducible training procedures.
6. Scope
6.1 In Scope
Custom tokenizer development.
Custom Transformer implementation in PyTorch.
Approximately 40M-parameter model configuration.
Pretraining from scratch on appropriately licensed/public-domain human-written text.
Task-specific fine-tuning for natural-language transformation.
Writing-style and readability analysis.
Semantic-preservation checking.
Model evaluation and benchmarking.
Local inference and user interface.
Experiment tracking and Git-based version control.
6.2 Out of Scope
Training a multi-billion-parameter frontier LLM.
Dependence on Claude, GPT, Gemini or another commercial LLM API for core generation.
Guaranteeing that output will evade any AI-content detector.
Using copyrighted books or datasets without appropriate rights or licensing.
Claiming that the custom 40M model is equivalent to a modern multi-billion-parameter general-purpose LLM.

11. Data Requirements
Human-writing corpus must be public-domain, appropriately licensed or otherwise legally usable for the intended project.
Data preprocessing shall remove corrupted, duplicated and unsuitable records.
The project shall maintain a clear record of dataset sources and licenses.
Training, validation and test sets shall be separated to reduce evaluation leakage.
Transformation pairs shall preserve the intended meaning and should cover multiple writing styles and lengths.
The dataset pipeline shall avoid using evaluation examples during training.

14. Success Criteria
A functioning custom Transformer can be trained from scratch and can generate coherent text at the selected scale.
The fine-tuned model performs the intended transformation on unseen test examples.
Meaning is retained at an acceptable level according to predefined semantic-evaluation criteria.
Readability and linguistic-variation measures demonstrate measurable improvement on the selected test set.
All reported results are reproducible from documented code and configuration.
The complete system can run locally without a commercial LLM API.
15. Risks and Mitigations
Risk
Impact
Mitigation
Limited GPU/RAM resources
High
Start with small models, use short context, gradient accumulation/checkpointing and scale only when stable.
Insufficient training data
High
Use a larger high-quality licensed/public-domain corpus and document data limitations.
Poor generated text quality
High
Improve data quality, training schedule and task-specific fine-tuning; benchmark against baselines.
Semantic drift during rewriting
High
Use semantic similarity checks and include meaning-preservation examples in fine-tuning.
Data licensing problems
High
Use only verified public-domain/licensed data and retain source/license records.
Overfitting
Medium
Use validation data, checkpoint selection and held-out test sets.
Project scope becomes too large
High
Deliver a working small-model baseline before adding larger experiments.
16. Ethical and Responsible Use
The project is intended to study natural-language generation, rewriting, readability and semantic preservation. It should not claim to provide a reliable method for defeating AI-detection systems. AI detectors can be inaccurate and change over time. Evaluation should therefore focus on measurable language quality and meaning preservation. Training data must be obtained and used according to applicable licenses and rights.
