Stage by stage

What each stage actually does, what it costs, and where it stands right now.

01
Fetch the corpus data/fetch.py done

Pulls parquet shards straight over HTTPS — 70% Project Gutenberg for natural narrative prose, 30% Wikipedia to keep the vocabulary from sounding Victorian. Shards are read batch-wise so peak memory is one batch, not one 400 MB file, and each is deleted after extraction.

Shard order is shuffled under a fixed seed. Sequential order tracks Gutenberg's catalogue ID, and the opening catalogue is Bibles and statutes — the first trial model trained on it generated pastiche scripture.

02
Clean, dewrap, split data/prepare.py done

Streams line by line, so a 3 GB corpus never lands in RAM. Rejoins hard-wrapped lines into real paragraphs, drops duplicates by hash, and groups consecutive paragraphs into documents of at least 200 characters.

Split assignment is a hash of the document text, not a shuffle. Re-running after adding more corpus therefore cannot move a test document into train — the evaluation-leakage requirement is satisfied by construction rather than by care.

03
Train the BPE tokenizer tokenizer/train_tokenizer.py done

Byte-level BPE, 16,000 merges, trained on the train split only. Byte-level means no token is ever unknown. The five special tokens are declared up front because the vocabulary freezes at training time — adding one later would mean retraining the tokenizer and re-encoding the entire corpus.

04
Encode to token IDs data/prepare.py encode done

Each split becomes a flat uint16 array on disk, documents separated by <eos>. Two bytes per token is why the vocabulary is capped below 65,536; training then memory-maps the file and slices random windows out of it, so the 1.6 GB of token IDs never has to fit in memory at once.

05
Pretrain training/pretrain.py running · ~49 h

Next-token prediction over the whole corpus. 8 sequences per micro-batch × 8 gradient-accumulation steps × 256 tokens = 16,384 tokens per optimiser step, which is how a 40M model trains on 4 GB of VRAM. Cosine learning-rate decay after a 200-step warmup, gradient clipping at 1.0, checkpoints every 500 steps.

Every flag is written into both the checkpoint and a JSON run record, so any result can be traced back to the exact configuration that produced it.

06
Fine-tune on paired rewrites training/finetune.py next

Pretraining teaches English. This teaches the one job: rewrite this passage, keep what it means. Supervised on paired examples, with the loss masked over the source half so the model is only graded on what it produces.

This is the stage that sets the output register — it is why the archaic flavour of a Gutenberg-heavy pretraining corpus is not fatal.

07
Evaluate evaluation/ next

Three independent questions, deliberately not collapsed into one score: is it a good language model (perplexity on held-out test), did the rewrite keep the meaning (embedding cosine similarity), and did the writing actually improve (readability, type-token ratio, repetition, sentence-length variation).

Plus a baseline comparison against a local pretrained model on the same test set, and one ablation. A model can score well on any one of these while failing the others — a rewrite that changes the meaning always reads more naturally.

08
The app app/streamlit_app.py next

Paste text, see its writing profile, transform it, read the two versions side by side with the semantic-similarity score between them. Model and tokenizer load from disk; if either is missing the app says which file it wants rather than failing with a stack trace.

What the hardware decides

Nearly every number above was chosen by 4 GB of VRAM and 8 GB of RAM rather than by preference.

The memory chain

A small micro-batch is all that fits, so gradient accumulation rebuilds an effective batch of 16,384 tokens across eight passes before each optimiser step. The corpus is memory-mapped rather than loaded. Every pipeline stage streams line by line. The tokenizer trains on a 200 MB sample rather than the full corpus, because the BPE trainer is the one step that genuinely needs its input in memory.

Two and a half days, and where they go

At the 4,600 tokens/second measured on this machine, 800M tokens takes about 49 hours — the Chinchilla-optimal budget for a 40M model is roughly 20 tokens per parameter, and undertraining shows up as a model that produces fluent-looking sentences with no coherence past a clause. The fetch and preprocessing together are under two hours. The training run is essentially the whole schedule.

What a 40M model can and cannot do

It can learn English well enough to rewrite a paragraph. It cannot be relied on to preserve every fact while doing so, which is exactly why semantic similarity is scored on every transformation rather than assumed. Expect the meaning-preservation gate to be the hard constraint, not fluency — and expect the pretrained checkpoint to sound archaic before fine-tuning, because 70% of its training text was written before 1929.

Where it stands

Stages 1 through 4 are built, tested and have run on the real corpus. Stage 5 is running now. Stages 6 through 8 are next, and none of them need the pretraining run to finish before they can be written and tested against a trial checkpoint.

The test suite covers what silently breaks: tensor shapes, the causal mask, the parameter count, checkpoint round-tripping, and whether the training loop can overfit a tiny batch — the fastest way to prove a pipeline is wired correctly is to confirm it can memorise four sequences.
