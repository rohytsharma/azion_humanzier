2. System Purpose
The HumanWriter system shall provide an end-to-end local platform for training, fine-tuning, evaluating and running inference with a custom approximately 40M-parameter decoder-only Transformer. The operational application shall analyze supplied text, transform it using the trained model and report measurable characteristics of the original and transformed versions.
3. High-Level System Architecture
The system shall be organized into six major layers: data management, tokenizer, model/training, task fine-tuning, evaluation and application/inference.
Layer
Main Components
Data
Source collection, cleaning, deduplication, filtering, dataset splitting.
Tokenization
Tokenizer training, vocabulary management, encoding/decoding.
Model
Embeddings, Transformer blocks, causal self-attention, feed-forward networks, output head.
Training
Causal language modeling, optimizer, scheduler, mixed precision where supported, checkpointing.
Fine-tuning
Paired transformation data, supervised fine-tuning and validation.
Evaluation
Perplexity, semantic similarity, readability, lexical diversity, repetition and human assessment.
Application
Local UI, inference engine, text analysis, output comparison and export.

7. Model Architecture Requirements
Module
Requirement
Token embedding
Map token IDs to learned vector representations.
Positional information
Provide positional information using a documented positional encoding/embedding method.
Transformer block
Use repeated decoder blocks with causal self-attention, residual connections, normalization and feed-forward layers.
Attention
Use multi-head self-attention with a causal mask.
Feed-forward
Use a nonlinear position-wise feed-forward network.
Output head
Project final hidden states to vocabulary logits.
Loss
Use causal cross-entropy/next-token prediction loss.
Parameter target
Approximately 40M parameters, with exact count reported in the experiment documentation.
8. Training System Requirements
The training pipeline shall expose configurable batch size, gradient accumulation, sequence length, learning rate, optimizer settings, number of epochs/steps and checkpoint interval.
The training system shall record training and validation loss.
The training system should support mixed precision where the selected hardware/backend provides stable support.
The system shall support gradient accumulation to simulate a larger effective batch size when VRAM is limited.
The system should provide optional gradient checkpointing for memory-constrained experiments.
The system shall save configuration metadata with checkpoints.
The system shall use a fixed or recorded random seed for reproducible experiments.
The training pipeline shall prevent validation and test data from being used for gradient updates.

11. Security, Privacy and Data Requirements
Core generation shall not require transmission of user text to third-party commercial LLM APIs.
User-provided text shall be stored only when the user explicitly requests local export or when logging is intentionally enabled.
Training datasets shall contain only material that the project is permitted to use.
Dataset source and license information shall be maintained as project metadata.
API keys or secrets, if any are used for unrelated tooling, shall not be committed to GitHub.

13. Acceptance Criteria
The system can train a custom decoder-only Transformer from scratch.
The final selected model is approximately 40M parameters or has a documented hardware-driven reduction.
The tokenizer and model can be saved and reloaded independently of the training process.
The model generates text without an external LLM API.
The fine-tuned model performs natural-language transformation on unseen test examples.
The system reports semantic preservation and writing-quality metrics.
The application runs locally on the documented hardware.
The repository contains reproducible setup instructions and experiment documentation.
The project clearly reports limitations and does not make unsupported claims about detector evasion.

15. Constraints
Current target PC has 4 GB GPU VRAM and 8 GB system RAM, so memory-efficient configurations are required.
A 40M-parameter target may require reduced sequence length, small micro-batches and gradient accumulation.
Training time will depend heavily on dataset size, token count, hardware and training configuration.
The M2 Mac can be used for development and MPS-based experimentation, but CUDA/Linux may be preferable for reproducible NVIDIA training.
No commercial LLM API is a required dependency for core functionality.
16. Future Enhancements
Scale the model beyond 40M parameters using stronger hardware.
Support longer context lengths.
Add additional writing styles and controlled transformation modes.
Add multilingual support if the tokenizer and training corpus support it.
Add a more advanced evaluation dashboard.
Release model adapters/checkpoints and reproducible experiment configurations where licensing permits.
